# 1. エンドポイントを 3 層に分け、管理面は前段で守る

- 日付: 2026-09-16（管理面の PATCH は 2026-09-29）
- 状態: 採用

## 背景

卓に入る鍵は、2024-10-19 に席ごとのトークンへ変えたときに、発行の口を公開したまま失われていた。
管理面（卓の作成・取得・削除）は、アプリ自身は認証していない。

## 決定

| 層 | エンドポイント | 守り |
|---|---|---|
| 管理 | `/version`、`/games`、`/games/:gid` | アプリは認証しない。前段（nginx の Basic 認証など）で守る |
| 入場 | `GET /join`、`POST /token` | `Authorization: Ticket` |
| 卓の中 | それ以外 | `Authorization: Bearer`（席のトークン） |

- 前段が守るのは `/admin.html`、`/js/admin.js`、`/games`、`/games/<数字>` の 4 つだけ。
- ticket は卓の鍵で、卓を作ったときに 1 つだけ発行する。token は席の権限で、gid と pid に紐づく。
- 卓は ticket で決まり、クライアントは gid を送らない。
- 管理面の操作は `/games/:gid` のメソッドとして足し、それより深いパスに置かない。

## 結果

- `/games/<数字>` より深いパスは参加者が使うので、前段で守らない。`/games` 以下をまとめて覆うと、
  参加者が締め出される（nginx なら末尾を `$` で止める。README に書いてある）。
- 管理面の操作を深いパスに置くと、前段の守りの外に出て、誰でも叩けるようになる。
- ticket があれば、卓の中のどの席のトークンも取れる。席同士は守らない（仕様）。
