# 4. トークンに卓ごとの uid を入れ、gid を再利用しない

- 日付: 2026-09-17
- 状態: 採用

## 背景

トークンは 1 日有効で、gid と pid を署名している。卓を保存するのは終了時だけ（ADR 7）なので、
異常終了すると起動中に作った卓は保存されず、次の起動で同じ gid が払い出される。
自動で繋ぎ直した古いページのトークンが、secret が同じなら、その新しい卓に通ってしまう。

## 決定

- 卓を作るときに乱数の `uid` を付けてトークンに入れ、`verifyToken` で卓の `uid` と照合する。
- 消した卓の gid は欠番にして再利用しない。保存するときも `null` にして位置を保つ。

## 結果

- 同じ gid で作り直された卓では、古いトークンは 401 になる。
- 席の名前を変えても、配ったトークンはそのまま使える（名前に依存しない）。
- secret（`--secret` か環境変数 `SECRET`）を与えないと起動のたびに変わり、再起動の前に配ったトークンは
  使えなくなる。そのときは起動時に警告する。
